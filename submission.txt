
Getting Your Hands Dirty with Video Output on Linux Using C++

Most people will use some video app to obtain video output on Linux. But video
output is still generally steeped in mystery and viewed as a magic blackbox
among the Linux community.  However the Lumiera team were confronted with having
to examine the magic blackbox themselves.

In this talk we demonstrate several well established mechanisms that can be used
to display video frames from a Linux desktop application.  We explain the technical
prerequisites to display video frames, discuss the challanges and we show some
widely avaiable technologies used to implement video disaply.

Lumiera is a video editing application under development in C++ -- which we use
here to illustrate how raw video output is at the heart of a video processing
render engine.

Getting Your Hands Dirty with Video Output on Linux Using C++

Most video formats are compressed and packed into containers for performace and
storage reasons. To edit a video it is essential to use a video in a raw format
as a sequence of individual frames. Raw video is processed as buffers filled
with pixel data. The pixels are encoded with respect to some colour space, and
there are a variety of standard mechanisms avaiable, which will be discussed
in the talk.

Handling raw video requires to access, process and transfer an enormous amount
of data. While modern CPUs are more than capable of managing such tasks in real
time, modern hardware is geared towards mastering these steps with precision and
speed. The downside would obviously require hardware specific programming, i.e.,
slightly different software implementations for the various GPUs on the
market. Fortunately the various hardware implementations can be wrapped in a
softare library that depends on vendor specific micro code, a driver in
the kernel.

For this talk we focus on displaying direct video output from a C++ application
that uses some long and well established standard frameworks that are widely

X Window System (aka X11, X) is a graphics protocol most widely used on Linux
and even older than Linux itself. It has many implementations, but currently the
most popular is that implemented by the X.org foundation which we use here.

X provides the user with a user interface that is the same for all hardware
and supplies the various hardware dependent components as libraries.  The X11
protocol specifies only primitive drawing features, so in addition to using X
another graphics layer can be used that provides the user with more high-level
graphics tools to the user and uses XVideo to implement these features.

X only provides primitive drawing features and does not take advantage of
graphical hardware features: OpenGl does. OpenGL is platform independent
protocol which provides an API. The implementation is often provided by
graphical card manufacturers, thereby reaping the wards of all the bells and
whistles available to a particular graphic card, but being portable as it must
here to the single API.

The new rendition of the OpenGl phoenix is Vulkan, but is still relatively new
and still emerging from its ashes; so we use OpenGL.
